# GSB Bugfix Task
## 题面
任务系统改成多线程排期后，运营配置的任务链开始互相踩：两个没有依赖的任务抢同一个执行槽，前置任务还没结束后续就开始了；资源只在排期开始时算一次，后面任务拿不到前面任务产出的奖励；截止时间只看任务本身，没看槽位什么时候空出来；失败任务占着槽位不放，把后面能做的任务全堵死。quest_scheduler.py 的 QuestScheduler 负责 schedule。实现要按前置依赖、截止时间、资源消耗和奖励做多槽位排期，同条件按截止时间和 id 稳定排序，槽位按最早空闲选择，资源不足或会超时的任务跳过，失败任务不能阻塞后面的任务；重复 id、缺失前置、环和非法时长要报错。

## 运行方式
```bash
python -m pytest tests -q
```
